# Commands reference

Derived from `Makefile`, `justfile`, root `package.json`, `apps/web/package.json`, and
`apps/api/pyproject.toml` (which defines no custom scripts — the api's "commands" are plain
`uv`/`uvicorn`/`pytest`/`ruff`/`alembic` invocations recorded in the
Makefile/justfile/CLAUDE.md).

## Root task runner (`make` / `just` parity)

`Makefile` and `justfile` define the **same target set** with **byte-identical shell commands**
for every target except `help`/`default` (listing mechanism differs, same purpose) and `clean`
(justfile splits Unix/Windows recipes; Makefile has one Unix-shell recipe). Run with `make <target>`
or `just <target>`.

| Target                           | What it does                                                                                                                                                                  | Notes                                                                                                                                                                                                                                                                                    |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `help` (make) / `default` (just) | Lists available targets                                                                                                                                                       | Make: custom `awk`-formatted listing of `## `-commented targets. Just: built-in `just --list`. Both are the default target when none is given.                                                                                                                                           |
| `doctor`                         | `bash scripts/doctor.sh` (just on Windows: through Git's `binash.exe`)                                                                                                        | Read-only toolchain check — git, Node 24, pnpm 11.5.2, uv, Python 3.14, Bicep CLI ≥ 0.30, az, just/make (+ optional Docker, gh, ODBC 18) — with the install command for the current OS next to anything missing; exit 1 while a required tool is missing. `/setup-dev-env` builds on it. |
| `install`                        | `pnpm install` (root) → `pnpm -C apps/web install` → `uv sync --directory apps/api`                                                                                           | Installs both services' dependencies.                                                                                                                                                                                                                                                    |
| `dev`                            | `pnpm install` → `pnpm -C apps/web install` → `pnpm run dev`                                                                                                                  | Runs both services **locally, no Docker**, concurrently (see [root `package.json`](#root-packagejson) below).                                                                                                                                                                            |
| `test`                           | `pnpm -C apps/web test` → `uv run --directory apps/api pytest`                                                                                                                | Fast unit/integration tests, no coverage. Offline — no database (the SQLAlchemy engine is lazy).                                                                                                                                                                                         |
| `test-cov`                       | `pnpm -C apps/web test:cov` → `uv run --directory apps/api pytest --cov=app --cov-report=xml`                                                                                 | Coverage variant — emits `lcov.info` (web) + `coverage.xml` (api), as CI does (`.claude/rules/40-testing.md`).                                                                                                                                                                           |
| `build`                          | `docker compose build`                                                                                                                                                        | **Docker image build** — do not confuse with the root `pnpm run build` npm script (JS/TS app build, no Docker; see below).                                                                                                                                                               |
| `up`                             | `docker compose up --build`                                                                                                                                                   | Builds + starts the full stack. `web` has `depends_on: api: condition: service_healthy` (`docker-compose.yml`), so compose **waits on the api's healthcheck** (`/health` polled every 10s, up to 5 retries) before starting `web`.                                                       |
| `down`                           | `docker compose down --remove-orphans`                                                                                                                                        | Stops and removes containers (not volumes).                                                                                                                                                                                                                                              |
| `logs`                           | `docker compose logs -f`                                                                                                                                                      | Tails logs from all running compose services.                                                                                                                                                                                                                                            |
| `clean`                          | **Destructive.** `docker compose down -v --remove-orphans` + removes root `node_modules`, `apps/web/node_modules`, `apps/web/.next`, `apps/api/.venv`, `apps/api/__pycache__` | Removes volumes (`-v`) and all local build artifacts/dependency installs. Make: single Unix-shell `rm -rf`. Just: `[unix]` recipe (`rm -rf`) and `[windows]` recipe (`Remove-Item -Recurse -Force -ErrorAction SilentlyContinue`) — this is why Windows users should prefer `just`.      |
| `fmt`                            | `pnpm install` → `pnpm run fmt` → `bicep format` on every `.bicep`                                                                                                            | Formats everything — delegates to the root `fmt` npm script (prettier + ruff; see below), then Bicep.                                                                                                                                                                                    |
| `openapi`                        | `uv run --directory apps/api python -m app.openapi_export` → `pnpm -C apps/web api-types` → prettier                                                                          | Regenerates **the API contract**: `docs/reference/openapi.json` and `apps/web/src/lib/api-types.ts`. Run after any change to the `/v1` surface; `tests/test_openapi_export.py` and CI fail when the committed contract is stale.                                                         |
| `infra-build`                    | `bicep build infra/main.bicep` + `bicep lint` + `bicep build-params` for `dev`, `staging`, `prod` (into `infra/.build/`, gitignored)                                          | Offline check of the use-case Bicep and its three param files; what CI runs. **Agents may run it.**                                                                                                                                                                                      |
| `infra-whatif` (`ENV=dev`)       | `az deployment group what-if --resource-group <from infra/platform/$ENV.json> --template-file infra/main.bicep --parameters infra/main.$ENV.bicepparam`                       | Preview for one environment. Needs `az login` + rights on that resource group. Just: `just infra-whatif dev`. The pipeline posts the same on every PR.                                                                                                                                   |
| `infra-deploy` (`ENV=dev`)       | `az deployment group create …` — **refuses any `ENV` other than `dev`**                                                                                                       | **Humans only, local `dev` only** (D5′). `staging`/`prod` are deployed exclusively by `.github/workflows/infra.yml` behind the GitHub Environment's reviewers. Never run by agents.                                                                                                      |

## Per-app script tables

### `apps/web` (`package.json` scripts)

| Script       | Runs                    | Notes                                                                                                                                                                                                                   |
| ------------ | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`        | `next dev -p 3000`      | Local dev server on port 3000.                                                                                                                                                                                          |
| `build`      | `next build`            | Production build (`output: 'standalone'` per `next.config.ts`).                                                                                                                                                         |
| `start`      | `next start -p 3000`    | Serves the production build — run `build` first.                                                                                                                                                                        |
| `test`       | `vitest run`            | Runs `src/**/*.test.ts` (lib + BFF route handler tests) once.                                                                                                                                                           |
| `test:cov`   | `vitest run --coverage` | Coverage variant; emits `coverage/lcov.info`. Presentational files (`page.tsx`, `layout.tsx`) stay out of the coverage denominator (`coverage.include` is `src/**/*.ts`) by design — see `.claude/rules/40-testing.md`. |
| `test:watch` | `vitest`                | Watch-mode unit tests.                                                                                                                                                                                                  |
| `test:e2e`   | `playwright test`       | **Manual/local only, not in CI.** Requires the full stack up (`make up` or `make dev`) — targets `WEB_BASE_URL` (default `http://localhost:3000`, see `playwright.config.ts`).                                          |

Run any of these with `pnpm -C apps/web <script>`.

### `apps/api` (uv / pytest / ruff / alembic invocations)

No `[project.scripts]` or task-runner section exists in `pyproject.toml` — these are the plain
invocations used by the Makefile/justfile/root `package.json`/`apps/api/CLAUDE.md`:

| Command                                                                                | Purpose                                        | Notes                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `uv sync --directory apps/api`                                                         | Install dependencies into `apps/api/.venv`     | Used by `make install` / `just install`.                                                                                                                                                                                                                                                                                                                                                                      |
| `uv run --directory apps/api uvicorn app.main:app --reload --host 0.0.0.0 --port 8000` | Local dev server with autoreload               | Exact command from the root `package.json` `dev` script (invoked by `pnpm run dev` via `concurrently`); `app.main` loads the optional `apps/api/.env` itself (`load_local_env()`), so no `--env-file` flag is needed.                                                                                                                                                                                         |
| `uvicorn app.main:app --host 0.0.0.0 --port 8000` (no `--reload`)                      | Production-style run                           | Documented in `apps/api/app/main.py`'s module docstring; run with CWD = `apps/api`.                                                                                                                                                                                                                                                                                                                           |
| `uv run --directory apps/api pytest`                                                   | Run the test suite                             | Used by `make test` / `just test`.                                                                                                                                                                                                                                                                                                                                                                            |
| `uv run --directory apps/api pytest --cov=app --cov-report=xml`                        | Run tests with coverage                        | Emits `coverage.xml`; used by `make test-cov` / `just test-cov`.                                                                                                                                                                                                                                                                                                                                              |
| `uv run ruff format app && uv run ruff check app`                                      | Format + lint (run **from inside** `apps/api`) | Per `apps/api/CLAUDE.md` / `.claude/rules/35-fastapi.md`; uses the project's own pinned `ruff==0.15.16` via the local venv.                                                                                                                                                                                                                                                                                   |
| `uvx ruff@0.15.16 format apps/api && uvx ruff@0.15.16 check --fix apps/api`            | Format + lint (run **from the repo root**)     | This is what the root `package.json` `fmt` script actually runs — a **different invocation style** than the CLAUDE.md convention above: `uvx` runs an ephemeral, pinned `ruff` (no venv activation needed) against the `apps/api` path as an argument, rather than `uv run` inside the project. Both reach the same pinned ruff version (`0.15.16`, matching the `dev` dependency group in `pyproject.toml`). |

#### Alembic (database migrations — no `make`/`just` target on purpose)

The URL comes from `DATABASE_URL` via `app.config` (never `alembic.ini`), so run these with
`apps/api/.env` in place or the variable exported. Applying a migration against a real
database is a **human** step — agents use only the offline / `heads` / `check` modes
(`.claude/rules/25-sqlalchemy.md`, [ADR-0004](../adr/0004-sqlalchemy-async-alembic-db-layer.md)).

| Command                                                                  | Purpose                                                 | Needs a DB? | Notes                                                                                                                                                               |
| ------------------------------------------------------------------------ | ------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `uv run --directory apps/api alembic heads`                              | List head revisions                                     | No          | Prints **nothing** today — `alembic/versions/` is empty.                                                                                                            |
| `uv run --directory apps/api alembic upgrade head --sql`                 | Render the upgrade SQL offline, for review              | No          | Offline mode: no DBAPI connection. Today prints only `BEGIN;` / `COMMIT;` (no revisions). Review this before anyone applies a revision.                             |
| `uv run --directory apps/api alembic revision --autogenerate -m "<msg>"` | Generate a revision from the diff between models and DB | **Yes**     | Needs a reachable **dev** database. Only models imported in `app/models/__init__.py` are seen. Post-write hooks run `ruff format` / `ruff check --fix` on the file. |
| `uv run --directory apps/api alembic check`                              | Report model/migration drift                            | **Yes**     | Fails when autogenerate would produce changes.                                                                                                                      |
| `alembic upgrade head` (human only)                                      | Apply pending revisions                                 | **Yes**     | Never run by the project or its agents. Also runnable from the image: `docker run --rm -e DATABASE_URL=… team-assistant-api alembic upgrade head`.                  |

From inside `apps/api`, drop `--directory apps/api` (`uv run alembic …`).

### Root `package.json`

| Script  | Runs                                                                                                                                                        | Notes                                                                                                                                                     |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`   | `concurrently -k -n web,api -c green,magenta "pnpm -C apps/web dev" "uv run --directory apps/api uvicorn app.main:app --reload --host 0.0.0.0 --port 8000"` | Runs both services concurrently, color-coded output; `-k` kills both on the first exit.                                                                   |
| `build` | `pnpm -C apps/web build`                                                                                                                                    | **Next.js app build only** — no Docker, no api step. Distinct from `make build` / `just build` (`docker compose build`) — don't confuse the two `build`s. |
| `fmt`   | `prettier --write . && uvx ruff@0.15.16 format apps/api && uvx ruff@0.15.16 check --fix apps/api`                                                           | Formats JS/TS/JSON/MD repo-wide with prettier, then ruff-formats + lint-fixes `apps/api` via `uvx` (see the `apps/api` table above).                      |

## Conventions

- **No pnpm workspace, no `--filter`.** Run every Node command scoped with
  `pnpm -C apps/<app> <script>` (e.g. `pnpm -C apps/web test`) — `pnpm --filter` does not apply
  because `apps/web` is an independent package with its own lockfile, not a workspace member
  (`.claude/rules/00-architecture.md`).
- **`uv run --directory apps/api …` from the repo root**, or `cd apps/api && uv run …`
  locally — both are used interchangeably across the Makefile/justfile/root scripts and
  `apps/api/CLAUDE.md`.
- **Windows:** `just` is recommended — its `clean` recipe has a native PowerShell branch
  (`[windows]`), and `justfile` sets `set windows-shell := ["powershell.exe", ...]` so every
  recipe runs under PowerShell. The `Makefile` assumes a Unix-like shell (`rm -rf`, `awk` in
  `help`) and needs Git Bash/WSL or equivalent GNU tooling on Windows.
- **Two different `build`s** exist at the root — `make build`/`just build` (Docker images via
  `docker compose build`) vs `pnpm run build` (compiles `apps/web` app code, no Docker, no
  api step). Same name, different scope — check which one you mean.
- **Migrations are never automatic.** Nothing in the task runner, the Dockerfile, or CI runs
  `alembic upgrade`; the api image merely ships `alembic.ini` + `alembic/` so a human can.
