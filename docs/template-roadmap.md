# Template roadmap — making the AI Accelerator carry a full AI project

> **What this is.** The backlog of changes to the **template itself** (not to any project built on
> it) so that a small team, with Claude doing most of the coding, can go from _clone → rename →
> plan → implement feature-by-feature_ with tests, docs and App Insights monitoring as
> non-negotiables. It is the template's own tracked roadmap; pick an item up by opening a PR that
> implements it and flipping its status.
>
> **Status markers:** `[ ]` todo · `[~]` in progress · `[x]` done · `[!]` blocked on a human.

> **Revision 2 (2026-10-04):** decisions **D3–D5** and **Phase 2** are **superseded** by [`template-roadmap-bicep.md`](template-roadmap-bicep.md) — Bicep on a cloud-team-owned shared platform (ADR-0012). Everything else here stands.

## 0. Decisions this roadmap is built on

Locked by the team (2026-09-28):

| #   | Decision                                                                                                                                                                                                                                                                                                                                            | Consequence for the template                                                                                                                                                                                                                                                                                                                                              |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | The template ships an **initial architecture document** that is the base of every project's architecture; the team updates the project layer of it by hand.                                                                                                                                                                                         | One living file, `docs/architecture/ARCHITECTURE.md`, split into a fixed _template baseline_ section and a team-maintained _project_ section. Skills read it; agents never rewrite the baseline. (ADR-0006)                                                                                                                                                               |
| D2  | **No local databases.** Every database lives on Azure. A project's own database must be **created on Azure first** (via infra), then used.                                                                                                                                                                                                          | No local DB container, ever. Alembic autogenerate / `check` / `db-introspector` run against the **dev** Azure database; applying migrations is a gated pipeline job or a named human. Tests stay offline.                                                                                                                                                                 |
| D3  | ~~Superseded~~ → **D3′** in [revision 2](template-roadmap-bicep.md). Infrastructure is deployed with **Terraform**, authenticated as the team's **app registration (service principal)**.                                                                                                                                                           | Infra moves to `infra/terraform/`. The existing Bicep observability stack is ported and retired (ADR-0007). Agents may run `terraform fmt/validate/init/plan`; **`apply`/`destroy`/`import`/state edits are pipeline-or-human only.** `az` stays denied to agents.                                                                                                        |
| D4  | ~~Superseded~~ → **D4′** in [revision 2](template-roadmap-bicep.md). **Resource groups and state storage pre-exist.** Exactly three resource groups (`dev`, `staging`, `prod`) host _all_ apps; each has **one** state storage account; each project's state lives in a **folder named after the project** inside it. Terraform never creates them. | Terraform uses `data "azurerm_resource_group"`, never `resource`. Backend config per environment via `-backend-config` files; state key = `<project-slug>/terraform.tfstate` in container `tfstate`. Naming convention for the storage accounts: **`st<org>tfstate<env>`** (see 2.4). The developer supplies the resource-group name at `init-project` time.              |
| D5  | ~~Superseded~~ → **D5′** in [revision 2](template-roadmap-bicep.md). **GitHub Actions applies Terraform in every environment**; developers may also run Terraform **locally against dev**.                                                                                                                                                          | `infra.yml`: plan on PR, apply on merge behind a GitHub Environment approval, one job per env with that env's SP secrets. Local: `make tf-plan ENV=dev` (and a documented, human-run `terraform apply` for dev only). Agents: plan only.                                                                                                                                  |
| D6  | **Azure SQL Database** (SQL Server engine) is the database — for the project's own database and for external read-only sources. **Not Postgres.** Network access is **public** with firewall rules for now.                                                                                                                                         | The data layer migrates from asyncpg to **`mssql+aioodbc`** (ODBC Driver 18, Entra/SP or SQL auth), Alembic guidance becomes MSSQL-specific, DB spans move to the SQLAlchemy OTel instrumentation, ADR-0004 is superseded (ADR-0008). Terraform provisions an Azure SQL server + database per project. Firewall: developer IPs + Azure services, private endpoints later. |
| D7  | **Azure AI Search** is the vector store for RAG.                                                                                                                                                                                                                                                                                                    | `app/ai/tools/retrieve.py` targets AI Search (hybrid/vector); Terraform module `ai-search`; api identity gets _Search Index Data Reader/Contributor_. No pgvector anywhere.                                                                                                                                                                                               |
| D8  | **No user auth for now.** Later, an **Okta** authentication module will be added.                                                                                                                                                                                                                                                                   | Phase 8 targets Okta (OIDC): session on the BFF, JWT validation in the api, behind `AUTH_MODE=none\|okta`. Until then projects are internal-only; every design doc states it.                                                                                                                                                                                             |

Assumptions (all confirmed by the team on 2026-09-28):

- **A1** ✅ confirmed 2026-09-28: **Azure SQL Database** (logical server + database; Terraform `azurerm_mssql_server` + `azurerm_mssql_database`).
- **A2** ✅ confirmed: the state container **`tfstate`** is created manually by the team together with the account; Terraform only writes blobs under `<project-slug>/`.
- **A3** ✅ confirmed: **one SP per environment**, each with access to **only its own resource group** — GitHub Environment secrets `ARM_CLIENT_ID/ARM_CLIENT_SECRET (or OIDC)/ARM_TENANT_ID/ARM_SUBSCRIPTION_ID` are therefore different per environment, and a local developer can only ever hold the `dev` SP's credentials.
